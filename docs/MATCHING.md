# Personal requirement matching

Open a job under **Mine stillinger**, then choose **Vurder personlig match**. All current CONFIRMED competency contributions are included automatically; the user does not select skill checkboxes. This includes literal documentary imports as well as personally confirmed facts. Drafts, inferred and rejected facts remain outside the factual matching evidence. If the profile has no confirmed evidence, upload/analyze documents in the profile first rather than manually creating competencies for each job.

The compact preview names the AI recipient/model and shows contribution and source-character counts. Competency contributions and the complete saved advertisement are inspectable in expandable, bounded readers. The advertisement can still be edited by removing whole lines. Approve each analysis separately; preview, recipient/model or confirmed-revision changes clear approval.

One approved Groq or Gemini call compares up to twelve source-backed requirements with the complete supported profile (up to 500 competency records). The old 30-contribution and combined 12,000-character matching cutoffs are removed. The complete saved advertisement is included by default (up to the existing 15,000-character snapshot limit). There is no lexical ranking/truncation of competency evidence. The backend requires the submitted owned ID/revision set to equal the current CONFIRMED set before spending AI budget. Repeated **exact** statement/context pairs are sent once in a passage dictionary; every skill, claim ID and revision retains a reference to its passage. Different contexts are never flattened together. Results retain all original claim snapshots and quote validation against those snapshots.

Profile names/contact fields, source notes and original files are not sent. Statement/context text itself can contain personal details; inspect or edit the profile before sharing it. The endpoint retains finite request bounds, ownership/CSRF checks, explicit model approval and the existing pilot request budget. Provider context/token quotas still apply: full-profile inclusion does not guarantee that every configured model accepts the largest possible profile. There is no silent model switch, retry loop or partial-evidence fallback. Failed calls retain the prior assessment and expose explicit alternate-provider recovery. Gemini matching allows 75 seconds; its web proxy allows 90, while other task timeouts remain unchanged.

Results distinguish **Documented relevance**, **Partial relevance** and **Needs clarification** with reason, original requirement quote, attributed candidate evidence and an optional question. These are AI judgments, not independent semantic certification. A course/listed skill must not be treated as production experience. Quotes must belong to selected candidate statements/context. Unsupported strong/partial results become unknown; individually malformed items are omitted, missing/unshared requirements are backfilled as unknown. Undocumented evidence does not establish a confirmed skill gap. Matching itself does not create or change a claim. Inline clarification explicitly saves the user’s own answer and personal confirmation through existing owned endpoints; it does not start another AI call.

V7 stores the latest owned result including the exact selected statement snapshots/revisions. Failed reanalysis preserves the prior result. Before saving, transactions recheck ownership/job existence and the complete confirmed revision set/status. Reopening computes stale status after edits/rejection/deletion and, for new automatic-evidence results, additional confirmations; stale results cannot serve as current evidence for later CV workflows. A process semaphore/default MATCH_AI_MAX_REQUESTS=10 bound this local pilot. Shared provider cooldown and Retry-After apply; the browser shows an actual wait without automatic resubmission.

Deleting a profile claim removes its claim history but can leave earlier copies in saved matching snapshots, as the claim deletion dialog discloses. Delete the saved job to remove its matching snapshot. This is not account deletion/provider deletion/backup deletion. External deployment and provider privacy terms remain separate work.

The displayed percentage is deterministic documented requirement coverage: required weight 2, preferred/unclear weight 1; supported strong relevance earns full weight, partial half, unknown no documented coverage. The UI explains the calculation and unresolved criteria. This is not hiring probability, and missing evidence is not a confirmed skill gap. See ADR 0027.

The saved-job card reads this persisted assessment and displays the same explained coverage percentage without calling AI. Missing assessments show a ready state; unavailable reads show a neutral unavailable state. Stale results are explicitly labeled for reassessment. Legacy selected-evidence results remain readable with their original attribution and staleness behavior.
