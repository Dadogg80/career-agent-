# Personal requirement matching

Open a job under **Mine stillinger**, then choose **Vurder personlig match**. Review/edit the source excerpt by removing entire unnecessary lines and inspect automatically preselected CONFIRMED statements and optionally adjust them. The preview shows the exact skill, statement, context and revision to share. Approve each analysis separately. Empty previews or unconfirmed/foreign/stale claims cannot be submitted. Changing the preview/selection resets approval.

One bounded approved Groq or Gemini call compares up to twelve source-backed requirements with up to thirty selected statements, within a combined 12,000-character limit. Long ads initially use a 6,000-character whole-line excerpt prioritizing stored requirement quotations; requirements absent from it remain unknown. The backend resolves selected IDs/revisions to current owned CONFIRMED records, not client-supplied statement text. Documents, name/contact profile fields, source notes and unselected claims are not sent. Selected statement/context text itself may still contain personal details; review or omit it before sharing. No browser search, autonomous agent or automatic retry is used. Initial selection is local; AI evaluates the approved evidence.

Results distinguish **Documented relevance**, **Partial relevance** and **Needs clarification** with reason, original requirement quote, attributed candidate evidence and an optional question. These are AI judgments, not independent semantic certification. A course/listed skill must not be treated as production experience. Quotes must belong to selected candidate statements/context. Unsupported strong/partial results become unknown; individually malformed items are omitted, missing/unshared requirements are backfilled as unknown. Undocumented evidence does not establish a confirmed skill gap. Matching itself does not create or change a claim. Inline clarification explicitly saves the user’s own answer and personal confirmation through existing owned endpoints; it does not start another AI call.

V7 stores the latest owned result including the exact selected statement snapshots/revisions. Failed reanalysis preserves the prior result. Before saving, transactions recheck ownership/job existence and selected revisions/status. Reopening computes stale status after edits/rejection/deletion; stale results cannot serve as current evidence for later CV workflows. A process semaphore/default MATCH_AI_MAX_REQUESTS=10 bound this local pilot. Shared provider cooldown and Retry-After apply; the browser shows an actual wait without automatic resubmission.

Deleting a profile claim removes its claim history but can leave earlier copies in saved matching snapshots, as the claim deletion dialog discloses. Delete the saved job to remove its matching snapshot. This is not account deletion/provider deletion/backup deletion. External deployment and provider privacy terms remain separate work.

The displayed percentage is deterministic documented requirement coverage: required weight 2, preferred/unclear weight 1; supported strong relevance earns full weight, partial half, unknown no documented coverage. The UI explains the calculation and unresolved criteria. This is not hiring probability, and missing evidence is not a confirmed skill gap. See ADR 0027.
