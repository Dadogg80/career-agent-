# ADR 0045: Individual source-bound CV passage assessments

Status: Accepted, 2026-10-13

A section-level index declaration cannot explain why only one of several profile/skills/work paragraphs received wording changes. Extend the existing approved CV_TAILORING call with passagePlans: one exact paragraphIndex, KEEP_UNCHANGED/PROPOSE_CHANGES/NEEDS_REVIEW action, concise individual reason, confirmed claim IDs and actual criterion indexes for every source unit. Include work-entry introductions and contribution bullets, preserving employer/client/role/date context. Protected section headings, identity/contact and historical titles/dates must remain unchanged; literal standalone recognized section-heading edits are also withheld by the service.

Validate each declaration independently. KEEP cannot contradict an actual proposal. PROPOSE requires a same-index retained proposal and all its evidence/criterion references. Missing/duplicate/invalid declarations become explicit unassessed NEEDS_REVIEW placeholders. Foreign indexes or omitted invalid proposals conservatively invalidate completion declarations. Numeric/source-year guards continue to withhold unsupported wording; valid proposals remain available. Any incomplete individual assessment downgrades its section's completion declaration. An accepted declaration proves neither semantic completeness nor factual truth.

Persist optional passagePlans in existing result/snapshot JSON; no migration or old-index rewrite. New sessions use prompt v5. Historical snapshots without this field keep the existing section-only display and receive no fabricated per-passage judgments. Frontend validation rechecks complete ordered source membership, proposal consistency and owned snapshot evidence/criterion references. The responsive ledger displays each reason, explicit keep recommendation, unfinished status and count of individually reasoned passages. User wording review stays separate.

The existing one-call output ceilings were Groq 3,500 and Gemini 8,192 tokens. CV_TAILORING alone now permits up to 16,384 output tokens on both adapters, including Gemini Interactions; other task ceilings, model defaults, input/review bounds, request budgets, quotas, cooldowns and explicit consent are unchanged. Use reasons of at most 300 characters, avoid repeating source text, and fail closed on truncated/malformed responses. A ceiling is not required usage and does not guarantee every maximum-sized input fits. No live calls are made by default.

This delivers finer source-unit reasoning, not a canonical employment/project graph, automatic CV readiness or guaranteed semantic accuracy. Unresolved passages do not confirm candidate facts; unchanged original wording and draft generation remain distinct from independent final-document approval. Contact extraction/recall, frozen-input match repeatability, component-wide design and final actual-file review remain subsequent priorities.
