# ADR 0021: Reviewed standard CVs and preserved application materials

Status: Accepted for the local pilot; unpublished implementation.

The owner selected a standard template with original retention, local hosting and controlled approval. Use existing confirmed claim/history revisions to build immutable draft snapshots, then approve DOCX/PDF generation explicitly. Store generated bytes and hashes rather than regenerating downloads. Represent application submission as a user-entered record linked to the exact approved CV; lock its date/CV/text once recorded.

Use PostgreSQL owner locks, optimistic revisions and owned foreign keys. Retain local private object storage; queue failed artifact deletion for explicit retry. Reuse PDFBox and JDK ZIP/XML with licensed embedded fonts. No Kafka, Temporal, new document-service dependency or AI call is justified by this synchronous bounded export.

Consequences: reliable material traceability and no invented CV experience. Arbitrary imported layouts, automated wording, portal submission and production storage reconciliation remain separate future work. Local draft copying supports correction without mutating an approved artifact. Application archive corrections need a later audited workflow.
